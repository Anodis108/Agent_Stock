Pattern dùng chung

Cả 5 worker chia sẻ đúng một khung ReAct

Thay vì viết lại logic gọi tool cho từng worker, build_react_subgraph() tạo ra vòng lặp seed → agent ⇄ tools → pack dùng chung — mỗi worker chỉ khác nhau ở system prompt, catalog tool, và cách đóng gói kết quả.

1seedKhởi tạo tin nhắn, xoá lịch sử lượt trước
2agentLLM chọn tool cần dùng qua bind_tools, có retrieval để không đưa quá nhiều tool cùng lúc
3toolsThực thi tool call thật (crawl vnstock, gọi API CafeF, đọc SQLite...)
4packĐóng gói kết quả thành schema Pydantic để hub đọc

Structured Outputs

Không parse JSON tay

Mọi quyết định của LLM — kế hoạch điều phối, câu hỏi viết lại, trích xuất bộ nhớ, câu trả lời cuối — đều ép theo schema Pydantic qua chat_parsed().

Guardrails 3 lớp

Đầu vào · Xử lý · Đầu ra

Chặn prompt injection và PII ở đầu vào, bọc system prompt chống ghi đè khi xử lý, kiểm tra số liệu vô căn cứ và ngôn ngữ ở đầu ra.

Memory hai tầng

Ngắn hạn khác dài hạn

Checkpointer (RAM/Postgres) giữ state một phiên theo thread_id. Qdrant giữ fact xuyên phiên về user theo user_id — hai kho độc lập.

Observability

Cây span thật trên LangFuse

Mỗi câu hỏi có 1 span gốc, mỗi worker mở span con riêng — tự dựng registry theo turn vì các nhánh song song của LangGraph không giữ context var đáng tin cậy.

Human-in-the-Loop

Chỉ một điểm dừng — đúng lúc chuẩn bị ghi dữ liệu thật

5 worker chạy tự do, không worker nào tự hỏi ý kiến người dùng. Graph chỉ interrupt_before=["hitl_commit"] — dừng đúng lúc chuẩn bị COMMIT tin/giá mới vào SQLite, chờ API /pr/approve mới đi tiếp.

Bước 1

Crawl xong

Worker lấy được tin/giá mới, đóng gói thành lệnh ghi chờ duyệt (pending), chưa commit.

Bước 2

Dừng lại

Graph treo ở hitl_commit, trả về câu trả lời tạm kèm số lệnh đang chờ duyệt.

Bước 3

Resume

Người dùng duyệt/từ chối qua API, graph tiếp tục đúng từ điểm dừng, không chạy lại từ đầu.
